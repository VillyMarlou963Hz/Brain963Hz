Title:
Mobile Coding: Work and Personal Offline Guidelines

Description:
Mobile coding is the practice of developing, editing, reviewing, and managing code from a mobile device while working offline or in limited-connectivity environments. It is designed for quick iteration, lightweight productivity, and uninterrupted progress when a laptop is unavailable or when privacy, portability, and focus are priorities. This workflow supports both professional work and personal projects by encouraging clean habits, secure practices, and efficient mobile-first development.

Purpose:
The purpose of mobile coding is to enable reliable software development from a phone or tablet without sacrificing structure, security, or quality. It helps maintain momentum, capture ideas quickly, and continue work in transit, at home, or in low-connectivity environments, while keeping projects organized and safe.

Core Principles:
- Clarity over complexity
- Security over convenience
- Small, reviewable changes over large risky edits
- Consistency across work and personal projects
- Offline resilience and backups
- Focused execution with minimal dependency on unstable connectivity

Rules for Mobile Coding:
1. Keep code changes small and intentional
- Prefer focused edits over broad rewrites.
- Submit or commit small, logical changes instead of large batches.

2. Work offline-first
- Assume there is no internet connection unless explicitly available.
- Prepare work in advance, sync when connected, and avoid depending on remote resources during offline sessions.

3. Separate work and personal projects
- Use separate repositories, branches, or folders for work and personal coding.
- Avoid mixing confidential work files with personal notes or side projects.

4. Never store secrets in code, notes, or local drafts
- Do not commit API keys, tokens, passwords, or private credentials.
- Use environment variables, secure storage, or encrypted vaults.

5. Commit often and meaningfully
- Make small commits that reflect a clear purpose.
- Use descriptive commit messages.

6. Keep backups
- Maintain local backups and cloud sync for important repositories or notes.
- Ensure work is not lost due to device issues or accidental deletion.

7. Verify before sharing or publishing
- Check for syntax errors, missing imports, and broken references before syncing or submitting work.
- Test what is possible offline, and validate fully when a proper environment is available.

8. Document assumptions clearly
- Write notes for unclear logic, blockers, or missing dependencies.
- Record decisions so future work remains understandable.

9. Protect privacy and professional boundaries
- Do not use personal devices for highly confidential work unless approved and secured.
- Keep personal and professional repositories separate and properly organized.

10. Respect device limits
- Mobile environments are smaller and more interrupt-driven.
- Prefer efficient tools, compact workflows, and lightweight project structures.

Guidelines for Work Projects:
- Use clean branch naming conventions.
- Keep issue or task references tied to the work.
- Use comments and notes to preserve context.
- Limit production changes while coding on mobile; prefer reviewable, low-risk edits.
- Maintain a clear work log of changes made offline.
- Avoid major refactors unless necessary and properly planned.

Guidelines for Personal Projects:
- Keep the workflow flexible and lightweight.
- Use personal repositories for experiments, prototypes, and learning.
- Maintain documentation so projects remain understandable over time.
- Use version control consistently, even for small projects.
- Keep project notes and ideas organized in one place.

Offline Workflow Guidelines:
- Prepare a local task list before starting.
- Save progress frequently.
- Keep a minimal set of essential tools installed.
- Maintain access to key files and local documentation.
- Prefer plain-text notes for ideas, tasks, and decisions.
- Use local backups to avoid loss.
- Keep a checklist of “what to do when connectivity returns.”

Best Practices:
- Use short, readable code with clear naming.
- Keep functions and files focused.
- Avoid large code blocks in mobile editors without review.
- Write meaningful comments only where needed.
- Revisit code later with a fresh eye before shipping it.

Recommended Mobile Coding Standard:
- Work in small steps
- Keep the codebase understandable
- Separate personal and professional work
- Protect credentials and sensitive data
- Use version control consistently
- Back up often
- Test as much as possible
- Document decisions clearly
